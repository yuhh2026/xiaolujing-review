# 原位编辑与清单

## JSON

```json
{
  "source_sha256": "中文原译文的完整SHA256",
  "changes": [
    {"page": 12, "old": "可能会增加科技支出", "new": "可能会挤出科技支出", "basis": "英文PDF第12页4.3.1节crowd out", "category": "翻译错误", "expected_count": 1}
  ]
}
```

page为中文PDF的1-based页码；basis另外记录英文页码，勿默认两份分页一致。每项须有basis，默认只匹配一次。扫描件、无可编辑文字、非Unicode CID、TJ复杂段、混合西文字体或不等长变化不属于快捷字槽编辑能力，脚本会拒绝；不是校译工作已经完成。

## 适用边界与替代处理

- 快捷路径只适用于已确认Identity-H且CID确实对应Unicode、同字符数、字槽宽度相容的内容流。不能仅凭Encoding名推断CID就是Unicode。
- 不等长修改可扩大至语义完整的小短语，前提是新译自然准确，不为固定字数牺牲含义。无法这样处理时，保留原字体、字号、基线，在原行/段落边界内重绘并检查后续文字；禁止未经检查的白块覆盖或默认换宋体。
- 复杂修改先单页试验。无法容纳时输出“未修改：原位置无法容纳”，不缩字或改变分页。用户改变约束前只推进独立可改项。
- 新增字形：检查glyf.numberOfContours及CID映射；原有glyph映射不等于实际轮廓存在。仅克隆字体资源供被改字符使用。完整匹配字体可补字；思源宋体/Noto同源替代要披露，尤其原文件另有Sa3m等回退字体时不能视为严格同字体。
- 图表数字、显著性星号和公式不是普通文字润色；未经英文逐项核对不改。英文也矛盾时保留证据，不擅自修研究结果。

## 节省重复开销

- inspect按文件SHA缓存页文本；apply仅处理清单页；verify只保存有变化页预览，未改页仍作像素检查。
- 补字缓存按完整字体内容哈希及字重区分；400/700静态字体只实例化一次。排查问题时只渲染目标页，确定方案后再做完整验收。
- 不把论文、全文提取、字体二进制、修改历史写进SKILL.md；本篇清单与疑点留本篇工作目录。
- 原位内容流编辑不支持的情况不能悄悄改为重新排版。依赖缺失、字体不匹配或未核实不是让用户重新描述已有背景的理由。
